# PANADERO Repository Structure

This repository contains one active local-laptop application. Existing legacy PDFs and database backups were **organized into archive folders, not deleted**. The active source paths remain unchanged so frontend relative links continue to work.

```text
PANADERO/
├── PANADERO-COSTUMER/
│   └── PANADERO-COSTUMER/PANADERO-COSTUMER/
├── PANADERO-STAFF/
│   └── PANADERO-STAFF/PANADERO-STAFF/
├── PANADERO-ADMIN/
│   └── Panadero-Admin/admin/
├── database/
│   └── panadero.sql                    Canonical schema + rubric sample data
├── docs/
│   ├── submission/                     Current editable Word files and video guide
│   ├── screenshots/                    Current interface screenshots
│   ├── CONTRIBUTIONS-AND-ROLES.md     Member roles and work descriptions
│   ├── FINAL-SUBMISSION-CHECKLIST.md  Final requirements checklist
│   └── archive/                        Preserved older PDFs and database backups
├── 02_Documentation/README.md          Pointer to current editable documentation
├── database_backups/README.md          Pointer to preserved database backup
├── server.js                            Node.js/Express API
├── login.html                           Compatibility redirect
├── PANADERO-ONE-CLICK.bat               Windows setup launcher
├── LOCAL-SETUP.md                       Setup and troubleshooting
├── .env.example                         Safe configuration template
└── package.json                         Node.js dependencies and scripts
```

## Which files should be edited?

- Backend/API behavior: `server.js`
- Database structure and sample data: `database/panadero.sql`
- Customer API services: `PANADERO-COSTUMER/.../assets/js/*-service.js`
- Staff API data layer: `PANADERO-STAFF/.../assets/js/staff-data.js`
- Admin API synchronization: `PANADERO-ADMIN/.../assets/js/admin.js`
- Visual design: active portal HTML/CSS/images under the three role folders
- Submission documents: `docs/submission/`
- Member contributions: `docs/CONTRIBUTIONS-AND-ROLES.md`

## Preserved archives

- `docs/archive/legacy-pdfs/02_Documentation/` contains the original PDF documentation files.
- `docs/archive/database-backups/` contains the previous database dump.
- `docs/ARCHIVE-INDEX.md` explains the preservation layout.

## Do not commit

- `.env` — contains local database credentials.
- `node_modules/` — generated by `npm install`.
- Temporary ZIP/MP4 exports — keep these in Drive or outside the source repository unless the group explicitly needs a versioned copy.
